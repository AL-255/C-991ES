# Parity, evidence and unresolved behavior

Documented instruction understanding, a readable C implementation and complete
firmware parity are separate claims. The frozen understanding ledger explained
46,094 unique decoded instruction starts out of 46,094, counting overlapping
spans once. Its 100% figure credits neither data bytes nor unsampled behavior as
executed tests.

A static explanation can cover a dead branch. An original CPU witness establishes
what the original ran. A prepared routine comparison proves its stated domain.
A whole-key workflow proves its actual continuation. A browser comparison against
host C proves that the bridge and display agree with that C engine. None alone
proves every operand, retained-memory alias, timing behavior or full workflow.

Production [scope](../../../csrc/scope.json) remains incomplete. Retained
controllers are readable high-level C; an original executor is a local test
oracle, not an implementation of a missing subsystem.

## Two implementation epochs

The redrawn browser was built from the committed **130-unit** engine with five
adapters. Public receipts bind actual CI pins, loaded HTTP assets and native-C
observations. Pending C changes were excluded.

The local **144-unit** implementation adds owned controllers and numerics. Its
full audit was stopped at the user's request. The 2026-10-05 stopping inventory
recorded 151 current passing, two stale/noncommon and three missing receipts out
of 156. This was a dated source-pin audit, not new execution or assurance that
receipts remain current after later source/tool changes.

Remaining records were BASE publication schema, TABLE UI, distribution-list
admission, device protocol and device session. Several failures arose from old
observers expecting generic bodies after C began owning them. Successors need
adoption and fresh execution. Historical passes cannot simply receive new source
hashes or PASS labels.

## Warm STAT cache metadata

A current 144-source O2 replay of the retained four-input harness found a genuine
RAM discrepancy at 829E..82BB: nine boundaries × 30 bytes, or 270 byte observations.
Values, LCD, control outcomes and all 41 poll comparisons matched. C retained
seeded 5A metadata where the original published different bytes. The full run
had four sessions and 765 boundaries.

This establishes a retained-memory discrepancy in the tested domain without
demonstrating a calculator-visible numerical error. It is unresolved; O3 and a
candidate fix had not run at stopping time. Relevant owners include
[statistics_advanced in fx_eval.c](../../../csrc/parse/fx_eval.c) and the
[statistics cache](../../../csrc/stats/fx_stats_cache.c).

Evidence points toward missing numeric scratch/resource publication rather than
a blanket cache overwrite. This is an investigation direction, not a proven
fix. Exact write order, normalizer workspace and continuation bytes still need
derivation from the original. Cache flag 1 must preserve/load the existing
80-byte cache. Captured final cache bytes must not become production constants.

Other limits include raw states outside ordinary UI admission, prefix stops that
do not reach final bodies, explicit unsupported requests and accelerated timers.
Physical hardware certification is not claimed.
