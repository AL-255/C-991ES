# Prepared random expression flow

Raw `8C` is Ran# (decoded category6/value66). Raw `C2` is RanInt#( (category1/value128). The parser uses the readable prepared numeric functions in `csrc/numeric/fx_random.c`; it does not execute firmware or use a host random-number generator.

Every completed draw publishes the full ten-byte seed immediately. The storage entry reads and writes physical `821C..8225` for each draw. The additive `fx_evaluate_prepared_random` entry accepts a caller-owned mutable session seed before its effects/result arguments. Copied calculus callbacks share the same memory or seed pointer. Existing public entry signatures and structure layouts are preserved. The older pure entry points use a fresh zero seed for their complete call; callers needing persistence use the explicit seed or storage entry. Input, seed, variable state and output occupy separate host storage.

Ran# reaches the native dynamic-constant checkpoint after prior-term and stack processing. At this point screen bit6 rejects it without a draw. It is accepted as an implicit-product operand. A later syntax, arithmetic or store error does not undo an earlier seed publication.

RanInt's screen-bit6 prefix guard precedes its own operator-slot push. The first comma retains the lower expression's value, checking the ten-record saved-value limit before evaluating the upper expression. CMPLX values occupy two records. Argument expressions execute in source order, then admission checks the upper value before the lower value under mask7. Loaded F*/6x/9x or nonreal CMPLX operands cause Math3 before the numeric leaf. Admitted but fractional, reversed or oversized numeric bounds cause Argument8 in the prepared numeric backend. A random bound may already have advanced the seed before either rejection.

A comma completes pending arithmetic, groups, unary functions and powers before reaching the nearest argument checkpoint or top-level Syntax2. After a two-argument call finishes, an unconsumed comma belongs to its enclosing operator context. For example, `C2 C2(1,10,20)` performs two draws: the same comma separates the outer bounds. `C2(1,10,Ran#)` performs the first valid draw and then fails at the extra comma; it does not evaluate the third argument. Store-follow syntax and screen-bit7 restrictions are checked before reducing an unfinished function. An explicit closing parenthesis completes its leaf first.

Calculus preflight performs actual numerical operations and dynamic draws before the first cancellation poll. Native helper `16A64..16A7C`, with preflight modeFF, replaces numerical status3/8 with canonical zero and success after an operation. Successful values and seed writes remain observable. Actual numerical samples use ordinary error propagation and the same persistent seed. A cancellation at the first poll can therefore retain one preflight draw.

The verification entry is `tools/test_eval_random_c.py`; ordinary finite-calculus regressions use `tools/test_eval_calculus_c.py`. Canonical reports pin the production C/H, complete quoted-header dependencies, input-only fixture sources, native host-event adapter and original ROM. Unsupported parser contexts/raw tokens and the numeric backend's forged8x/raw-add-cycle limits remain explicit; such outcomes are not successful native-result parity. These prepared APIs do not model every CPU scratch byte, caller-output/CPU-frame aliases, display scheduling or history/Ans publication.
