# Prepared VERIFY main workflow

The new entry is ordinary live mode137 (`0x89`), screen1. It reuses the shared
editor, INPUT preparation, scalar parser, error-key controller and result
renderer. It does not decode the expression as COMP or execute firmware code.

`fx_evaluate_verify_operand_source` is the existing physical scalar evaluator
with a named local result. Native relation delimiters terminate an operand
after its pending function/group reductions. `=` never enables the SOLVE
equation flag. Each operand starts with its own value-depth zero and keeps its
actual mode137 token interpretation: raw `i` is zero, `C8` follows the native
reference admission, and raw `2F` is implicit multiplication. The global
result is not replaced by these local operand results. Its address remains
the inherited sample/error sink; arbitrary aliases with that sink or CPU
local frames are outside this port's contract.

`fx_verify_chain` follows138EE: decrement/increment only the cursor's low
byte, poll5550 before every later operand, and evaluate every relation even
after an earlier false result. Equality can bridge a relation family; an
incompatible non-equality family produces SyntaxError. The predicate is
right-prepared first, then left. Compact surds emit their ordered six-record
component pool before comparison. The finite comparator includes the guarded
decimal subtraction and the native quotient-against-one stage for non-strict
relations. It is not a comparison of host floating point values. Only final
EOF publishes Boolean real plus zero secondary; errors/cancellation retain
the prior global pair and already committed variables/workspace/peripherals.
Odd Boolean outputs use the native five aligned word stores.

`fx_verify_controller` wraps the real ordinary main controller. Mapped keys
are prepared caller inputs in80F5/80F7. The actual VERIFY denylist is read
from1081..1089. Error recovery uses genuine physical key masks. Modifier
normalization precedes the live-mode empty-expression test in EE7C: an empty
VERIFY expression with a non-DEL key preserves the editor's TRUE/FALSE prompt
and skips the natural viewport. Both the main redraw and public INPUT
presenter use that policy. The direct presenter correction is independently
reviewed static shared policy; no separate native direct-present corpus is
claimed. Mode137 does not append ordinary calculation history: the native
history mode provider returns zero. Ans commits through the shared INPUT
success path; PreAns keeps its existing COMP-only policy.

The portable verifier preserves three distinct scopes at O2 and O3:

-384 prepared original predicate calls per build compare status, truth,
  returned record, right input and60-byte surd pool.
-180 fresh original138EE calls per build compare records, status, cursor,
  poll/operand/predicate counts, real variable bank and60-byte pool.
-96 C main calls per build compare against two immutable genuine original
  D9EE archives:95 returns and one retained error wait. The original main
  ran from authored globals/keys after the6F86..6FD8 startup-data prefix;
  C independently runs its startup-data initializer. Archived native RAM is
  comparator-only. Remaining RAM includes the LCD, result pair, expression,
  globals, variable bank, history and MMIO. Exclusions are8000..80DB,
  8640..87CF and the measured cumulative original CPU-stack interval for
  each scenario. This is not full64KiB equivalence, key scanning, full boot
  or uninterrupted hardware main-loop parity.

The source/fixture/compiler/artifact hashes are guarded before and after
execution; compiled sizes and offsets cover the number, physical storage,
chain result and cancellation ABI. Fifteen real copied-root refusal controls
exercise reduced/custom canonical publication, invalid schemas and Python
optimization. A custom math fixture must use `--no-report` or a private
report; main inputs and observations must keep their exact original custody.
The default canonical report requires the installed root tool, root sources,
unchanged complete fixtures and both builds. The historical original reports
retain their original path and artifact metadata rather than being retagged
as current C proof. The separate main archives are byte-preserved.

Raw relation dispatch addresses beyond the six mapped native predicates,
wrapped ROM operand continuations, advanced calculus and generalized physical
source/output/workspace aliases remain explicit host boundaries. The whole
firmware C implementation is still incomplete. Documented understanding is
100.00%, independently of these execution scopes.
