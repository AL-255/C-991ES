# Matrix and vector numerical kernels

`fx_linalg.c` implements the prepared firmware numerical entries as readable C formulas. It uses the existing finite decimal, rational, surd and complex magnitude routines. The production library contains no ROM, CPU interpreter, generated instruction translation or host floating-point operations.

A value contains its ten-byte evaluator reference, two dimensions and nine ten-byte scalar cells. Reference headers `6x` and `9x` identify matrix and vector slots; their low nibble selects native storage. These rich references are separate from scalar number classifications. Native dimensions reside at `80E0 + 2*slot`, and backing storage at `829E + 90*slot`. Every object uses a physical row stride of three, including small matrices and two-dimensional vectors.

The result preserves dimensional and backing state even when the reference becomes a scalar or error. This makes native partial updates visible: componentwise operations commit each cell; matrix products commit a zeroed nine-cell temporary only on success, after updating dimensions; transpose swaps all nine cells. Determinant and vector dot/magnitude return a scalar in the reference without replacing backing storage. Inverse builds its adjugate in place and scales with the fraction-preferring division entry. Negate, square and cube use the same finite operation order and cancellation checks as their native wrappers.

`exact_math` is the already resolved exact-output permission used by the magnitude leaf. Display settings select elementwise rounding. `cancel_at` supplies an explicit prepared timer response: zero permits every check; a positive number cancels at that check. `cancellation_checks` reports the checks actually reached. Physical timer, interrupt and keyboard scheduling are outside this numerical API. Canonical matrix dimensions are 1..3 by 1..3; vectors use one row with two or three columns. Zero dimensions reproduce Dimension9; other dimension bytes above three are rejected by the host API because they would address beyond this fixed typed storage.

The canonical suite `python3 tools/test_linalg_c.py` compares all nine cells, dimensions, the complete reference record, native status and cancellation count against the unchanged original ROM/CPU. Its test-only harness supplies RAM8E00 at native PC5564 to represent the prepared timer response; it does not patch an instruction. It covers exact and finite decimal cells, boundary exponents, marked records, numerical errors, inactive cells, input/output aliases, scalar aliasing into the payload and cancellation boundaries. Verification provenance is in `analysis/c-verification/linalg.json`.

`fx_linalg_reduce.c` adds complete prepared REF/RREF entries. It selects rows first by leading nonzero position, then by absolute magnitude in the first pivot column. Its private comparison helper accepts the preceding absolute-value records; it is not a general signed comparison API. It normalizes leading pivots with the fraction-preferring scalar divide, forms each elimination cell as `pivot * lower_cell - pivot_row_cell * lower_coefficient`, then normalizes a private row. A native exponent predicate admits plain-decimal values at or below exponent −11 as zero only during private elimination-row normalization. This differs from replacing the finite sequence with ratio-first Gaussian elimination.

Reduction preserves the firmware's recursive column shifts, destructive row-prefix extraction and saved pivot-row merge. A completed ordinary elimination stage commits all nine cells together; interrupted recursive stages retain their destructive partial updates. RREF removes upper coefficients in ascending pivot-row order, and clears each coefficient only after its terminal cancellation check. `python3 tools/test_linalg_reduce_c.py` verifies the complete backing, dimensions, reference/status and check counts; canonical source pins are in `analysis/c-verification/linalg_reduce.json`.

The two modules cover twenty-one prepared kernels and wrappers. Evaluator reference allocation/rewriting, persistent object editing, matrix/vector display composition and physical timer servicing remain separate work. Whole-firmware completion is false.
